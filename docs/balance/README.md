# Баланс бойцов

Здесь лежит всё, что нужно, чтобы продолжить работу над балансом с того же места: цели, метод, инструменты, сырые результаты и известные проблемы. Числа ниже получены этими же скриптами, их можно перепроверить.

## Цели

1. **Внутри редкости нет меты.** У каждого бойца есть соперники, которых он побеждает, и соперники, которым он проигрывает (камень, ножницы, бумага). Нет бойца, который бьёт всех, и нет бойца, который проигрывает всем.
2. **Редкость сильнее.** Боец редкостью выше почти всегда побеждает бойца редкостью ниже, а через одну ступень побеждает всегда.
3. **Чем реже боец, тем больше он умеет.** Это лестница:

| Редкость | Что есть у бойца |
| --- | --- |
| Обычный | Обычный удар и один приём за 1–2 энергии |
| Редкий | Приём и талант с одним свойством |
| Эпический | Приём, суперприём за 3 энергии и талант |
| Легендарный | Приём, суперприём и двойной талант. Только у легендарных бывает «последний рубеж» (один раз пережить смертельный удар) |

Таланты (`trait`) работают сами: `armor` (удары без пробития слабее), `thorns` (атакующий теряет HP), `regen` (лечение после своего хода, если боец не горит), `rage` (сильнее на половине здоровья), `fireproof` (не загорается), `steady` (не теряет атаку и энергию), `quick` (лишняя энергия на старте), `vamp` (обычный удар лечит), `laststand`. Новый эффект приёма `shatter` сбивает щит и защиту соперника. Всё это описано в `public/js/duel-engine.js` и покрыто тестами в `tests/duel.test.mjs`. Лестницу проверяет `tests/data.test.mjs`.

## Метод

**Идеальная игра.** Бой один на один детерминирован, поэтому его можно решить точно: `tools/lib.mjs` перебирает минимакс с мемоизацией по всем состояниям. Для каждой пары считаются оба порядка ходов, второй ходящий получает +1 энергии (темп, как в игре). Итог пары `s(a, b)` — среднее по двум порядкам:

- `1` — a выигрывает при любом порядке ходов;
- `0.5` — исход решает тот, кто ходит первым (в отчётах это «even»), или ничья;
- `0` — a проигрывает при любом порядке.

**Игра ботов.** Дополнительно для каждой пары играются бои `botMove` против `botMove` (60 боёв в итоговых матрицах, 24 в подборе). Так выглядят бои с дикими бойцами и случайная игра живого человека.

**Подбор чисел.** Эффекты и таланты придуманы руками под блюдо (`results/roster-draft.mjs`), а все числа (HP, атака, стоимость и сила приёмов, сила талантов) подбирает отжиг в `tools/tune.mjs`. Диапазоны HP и атаки зависят от редкости. Функция штрафа `J` складывается из частей:

| Часть | Что штрафует |
| --- | --- |
| `spread` | средний счёт бойца в своей редкости далеко от 0.5 |
| `even` | доля пар, которые решает порядок ходов (вес `EVEN_W`) |
| `counters` | у бойца мало явных побед или мало явных поражений в своей редкости |
| `bot` | у ботов счёт бойца далеко от 0.5 |
| `cross` | соседняя редкость выигрывает реже 80% или чаще 94%, через ступень реже 95% |
| `draws`, `top`, `unsolved` | ничьи, боец со счётом выше 0.68, пары, не решённые за бюджет состояний |

## Результаты

### Что было до (`results/report-before.txt`)

Старый ростер из `main` с одним приёмом у всех:

- В каждой редкости была мета. Обычный Цезарь Ролл набирал 0.82 и не проигрывал никому, редкий Цыплёнок барбекю 0.95, эпический Четыре сыра 0.94.
- Были бойцы без единой победы в своей редкости: Кола 0,4 л (0 из 20) и Шеф Баскет (0 из 11).
- Все шесть пар легендарных решал порядок ходов.
- 8 случаев, когда обычный боец побеждал редкого при любом порядке ходов (7 из них против Шеф Баскета).

### Подбор (`results/tune-round1.txt`)

## Известные проблемы и что дальше

1. **Много пар решает порядок ходов**, особенно у обычных (половина пар). В игре ходит первым тот, кто начал бой, так что это скорее 50 на 50, чем мета. Это главный кандидат на следующую доводку: `EVEN_W=3` в `tune.mjs` повышает его вес.
2. **Межредкостный разрыв почти 100%.** Цель была 80–94% для соседней редкости, но при идеальной игре и в бою один на один не достигнута. В реальной игре это смягчают уровни и дикие бойцы, которые подстраиваются под команду (`wildFighter` в `game.js`).
3. **Не решены точно** командные бои 3 на 3 (порядок выхода, лечение команды) и уровни бойцов. Матрица считает только бои один на один на базовых характеристиках, как в дуэлях с друзьями.
4. **Нужна проверка на живых игроках.** Бот не копит энергию на суперприём так, как это делает человек.

## Инструменты (`tools/`)

Все скрипты работают на Node.js 24 и импортируют движок прямо из `public/js/duel-engine.js`. Ростер можно передать как `.mjs` с `export const FIGHTERS` или как JSON (результат `tune.mjs` или просто объект бойцов).

```sh
cd docs/balance/tools
# Полная матрица, удобно резать на шарды и гонять параллельно
for i in 0 1 2 3 4 5; do node matrix.mjs ../results/cand-8.json /tmp/m-$i.json $i 6 & done; wait
# Отчёт: счёт внутри редкостей, кто кого бьёт, межредкостная таблица, апсеты
node report.mjs ../results/cand-8.json /tmp/m-*.json
# Отжиг: ростер, сид, число итераций, файл результата (пишется каждые 200 итераций)
EVEN_W=3 T0=0.01 node tune.mjs ../results/cand-8.json 42 1500 /tmp/tune-42.json
# Перенос результата в игру (комментарий «Стаканы колы» потом вернуть руками)
node emit.mjs /tmp/tune-42.json ../../../public/js/fighters.js
```

Один запуск `tune.mjs` занимает около 1.5 часа на одном ядре сервера. Полная матрица режется на шарды и считается параллельно. На сервере удобно запускать около 20 сидов параллельно через `setsid nohup … &` и потом проверять полной матрицей только три лучших по `J`. После переноса в игру обязательно прогнать `npm test`: тест лестницы проверяет, что средние HP и атака растут с редкостью.

## Файлы (`results/`)

| Файл | Что это |
| --- | --- |
| `roster-before.mjs`, `matrix-before.json`, `report-before.txt` | Исходный ростер из `main` и его полная проверка |
| `roster-draft.mjs` | Черновик с талантами и суперприёмами, от которого стартовал подбор |
| `tune-round1.txt` | Итоги 20 запусков отжига, отсортированы по `J` |
| `cand-8.json`, `cand-9.json`, `cand-12.json` | Лучшие ростеры подбора |
| `matrix-seed*.json`, `report-seed*.txt` | Полная проверка каждого кандидата |

Формат матрицы: ключ `"a b"` — бой, где `a` ходит первым. `r` равно 1, если выигрывает `a`, −1, если `b`, 0 при ничьей и `null`, если позиция не решена за бюджет. `bot` — доля очков `a` в боях ботов.
